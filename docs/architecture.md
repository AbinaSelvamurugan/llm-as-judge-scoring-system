# Architecture and reproducible records

`judgebench.schemas` validates items, rubrics, judgments, human scores and API configuration. `datasets` bounds bytes and records and rejects duplicates. `storage.Store` provides SQLite transactions, foreign keys, versioned rubric definitions, immutable imported task records, frozen `run_items`, a run config/prompt snapshot, failure and success results, human annotation revisions, adjudications and experiment artifacts. `judge.ClaudeJudge` checks provider model availability, calls official structured output `messages.parse` or explicit unstructured fallback, validates score semantics and records metrics. `metrics` uses pairwise complete-case matches with item-cluster bootstrap. `experiments` uses repeated paid paired observations, not heuristic answers. `reporting` serializes persisted findings into several formats. `app/streamlit_app.py` offers ten views. The CLI uses the same services, not shadow implementations.

For reproducibility, retain database backups, the exact imported data, rubric JSON, model identifier, response model, run item snapshot, prompt string, runtime dependency versions, selected human reference strategy, bootstrap seed and statistics options. Prompt/system snapshots are in `runs.prompt_template`; the effective user packet is deterministically constructed from a snapshot item, source evidence, rubric JSON and stated reference policies. The stored raw provider scores and aggregate are immutable for completed items within a run, barring explicit database-owner access.

SQLite is single-host infrastructure; run scripts sequentially or through a controlled queue. SQL transactions prevent partially inserted batches. Database deletion removes study records permanently; back up before migration or retention actions.
