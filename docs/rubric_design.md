# Rubric design and criterion anchoring

Default anchored definitions are in `configs/rubric.yaml`; every criterion has description, separate scoring instructions, positive and negative examples, `anchors`, evidence requirement, `abstain_when`, weight, enable flag and optional critical threshold. Scores and scale types are schema-checked with Pydantic. Binary criteria have exactly {0,1}; ordinal criteria have exactly {1,2,3,4,5}. In particular, factual error is not conflated with relevance, and unsupported claims are not automatically classified as contradictions.

The first version is a general-purpose starting rubric, not a universal human standard. Before any substantive study, review anchors with domain experts and pilot independent annotators on development examples. Record changes as a new version and repeat human calibration. Keep adjudication records in a separate table; preserve individual labels. If source evidence is absent, grounding requires abstention; Pydantic and rubric validation reject a non-null grounded score without a supplied source.

Weights are normalized across assessed (not abstained) enabled criteria and all ordinal values use a common [0,1] normalization. Ordinal means are descriptive summaries only. Default pass is normalized >=0.65, provided that all enabled criteria are assessed and no critical override occurs. Any critical score at/below its threshold triggers fail even if other criteria abstain. Strong policy recommendations should rely on criterion-specific thresholds and manual-review gates, not averages alone. The default rubric uses clarity and safety as disabled optional examples so safety can be enabled **only** with a defined task-specific policy and evidence.
